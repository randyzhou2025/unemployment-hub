# 社保医保模块 · 上海试点与城市扩展

适用项目：`/Users/Randy/Cursor/UnemploymentHub`。

## 入口与页面

- 小程序首页「社保医保」或工具页入口；旧专题链接也会跳转到新模块。
- 本地预览：http://localhost:3072/#/package-insurance/home/index
- 同一局域网：http://192.168.1.108:3072/#/package-insurance/home/index
- 后台：http://localhost:3071/ →「社保医保政策」。局域网地址随 Mac 网络变化。
- 页面：模块首页、三步方案选择、路径详情、费用与医保账户说明。使用原生导航栈、固定底部操作、本机保存选择；没有新增登录门槛或云端个人档案。

## 先维护上海

后台选择「上海」。三个编辑页分别维护：

1. **费用与有效期**：基数上下限；养老、医保及账户费率；各自生效与截止日期；居民医保年度、指定年龄档及个人年费；人工核查日期和下次复核日期。
2. **资格、路径与办理**：领金医保代缴、领金个人养老、居民医保候选范围、医保单缴是否需确认；资格、等待期、账户、临近退休支持说明；五条路径的条件、办理步骤、官方入口名称和来源引用。
3. **官方来源**：维护标题、文号、发布机构、HTTPS 原文。引用的标识必须存在；改标识时要同步调整所有引用。

「保存草稿」不会改变前台。「发布城市政策」使用当前完整表单；先核查并勾选发布确认。若需撤下城市，关闭「前台开放」后发布；只关草稿开关不会撤下已发布版本。编辑角色只能查看，管理员和复核员可保存、发布。保存和发布均写操作记录。

重新部署、打开页面、保存草稿都不会刷新核查日期。超过人工复核日期或某项费用有效期时，精确报价暂停；居民医保年费只在所标待遇年度展示，不作下一年度报价。金额是整数分，比例是基点（界面输入20代表20%）。

## 新增城市

1. 选择「新增城市」，输入六位行政区划代码和名称。新配置为空，默认不开放，不复制上海数据。
2. 收集本地官方文件，先维护来源，再逐项填费用、适用日期、规则与办理内容。未载明截止日可留空，不能自行推断固定到期日。
3. 居民医保候选类别只表示可以进一步核查，不能代替完整资格。外地特殊身份已向经办机构确认资格时，用户可自行标明；小程序仍显示条件和提醒。
4. 保存完整草稿，核对五条路径、金额、年/月单位、户籍条件、等待期、官方入口、账户计入规则及退休支持。
5. 勾选核查确认，开启前台开放并发布。前台城市选择器随后显示该城市；未发布或停用的城市接口返回404。
6. 在「内容与指南」选择社保医保分类、指定城市，可为新城市发布资讯；全国通用内容也会归集。原有失业金金额工具仍仅支持上海，不会因新城市开放而套用上海标准。

取消未保存的新增或修改，可用「放弃修改」。已保存草稿和发布版本不会删除。

本版城市费用模型适用于同一可选月基数乘费率的职工保险和一档居民医保年费。若新城市存在不同险种基数、定额医保收费或更多特殊计算规则，先扩充对应字段和计算测试，不能把不适用的政策硬填成上海模型。没有构建全国政策规则引擎。

## 用户建议边界

- 五条路径是便于理解的参保情形，不是官方套餐。
- 正在本地领金、希望暂停或续缴养老：分别列医保基金代缴与个人养老参考；先核对实际代缴和待遇记录。
- 待审核、异地领金、状态未知：不直接认定基金代缴或个人零自付。
- 有实际灵活就业：展示当地资格和条件成立时的两项费用。只想缴医保时提示经办确认，不默认强制捆绑两险。
- 居民医保：核对参保范围、是否已有其他基本医保；报价明确年龄档、待遇年份、仅医保不含养老。未询问年龄，不将某档年费认定为个人账单。
- 重新就业：直接进入单位参保路径，不用个人自费取代单位责任。
- 养老暂停不清零既往年限，暂停月份不新增；不承诺可任意补缴。
- 临近退休专项支持按条件先缴后补，试算不预先抵扣补贴。
- 不确定时展示待核实事项，最终资格、待遇起始时间与费用由经办机构核定。

账户实际按医保年度预计入、清算，不承诺每月固定到账；其余筹资不能简单理解成全数进入某个单一账户。上海灵活就业医保原则等待6个月，原正常待遇中断后3个月内按规定衔接可有例外。居民医保也须核实等待期。

初始来源及原文URL集中在 `apps/api/src/db/insurance-policy.ts`，前台原文按钮复制网址供浏览器打开，办理事项名称见步骤。参考附件：`/Users/Randy/Downloads/失业社保医保缴纳政策方案.pdf`；实际政策以已核查官方原文为依据。

## 数据、升级、部署

- PostgreSQL 数据库 `unemployment_hub`，`app_config` 的 `insurancePolicies` 保存城市数组，每项含独立 `draft` 和 `published`。本次已执行增量种子初始化，只在缺少配置时插入，保留现有账号、内容和首页排序。
- 用户选择：微信本机 `uhb:v1:insurance-answers:<cityId>`；城市偏好 `uhb:v1:insurance-city`。不上传问卷答案到 API。修改就业状态或户籍时，之前的资格确认重置；其他仍适用选择保留。
- 新增 `/api/v1/insurance-cities`、`/api/v1/insurance-policy/:cityId`；后台 `/api/v1/admin/insurance-policies` 及 `PUT /:cityId`，沿用 Cookie、来源校验、角色权限、事务与审计。城市配置写入串行化以避免不同城市同时保存互相覆盖。
- 没有新增数据表或SQL迁移。服务端更新需同时部署 API、后台及微信包；先备份数据库，再按现有《部署上线指南》重建服务并执行增量种子。不要只上传前端后连接旧API。
- 本地 `pnpm dev`；微信本机联调 `pnpm build:weapp:local`。正式部署配置 HTTPS API 后使用 `pnpm release:weapp`；本地跳过域名校验不适用于正式发布。
- 回滚前保存当前数据库备份；恢复配置可由后台重新发布上一份核查数据或恢复数据库备份。前台未开放城市不会出现在城市选择器。

## 验收

自动检查包括费用分段、整数分核算、自选基数越界、账户合计、到期与跨年、跨城市、未知资格、待审核、居民医保候选范围、单位责任、来源和有效期校验；真实 PostgreSQL 测试验证城市草稿/发布隔离、撤下、审计、身份和权限。

本次仅本地环境及微信开发者工具验收；不等于真机验收、云端部署或微信审核通过。真机还需检查返回与键盘、动态字体、原文复制和真实网络；在正式域名校验开启、HTTPS API运行的条件下再验收发布包。
