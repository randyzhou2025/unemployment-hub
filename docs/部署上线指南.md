# 失业有数：Git 部署三步

程序统一通过 Git 管理：首次 `git clone`，以后 `git pull --ff-only`。不再上传源码目录或把编译文件提交进 Git。

| 项目 | Git 仓库 / 服务器目录 |
| --- | --- |
| 失业有数 UnemploymentHub | `https://github.com/randyzhou2025/unemployment-hub.git` → `/opt/unemployment-hub` |
| 原有 padmin | `https://github.com/randyzhou2025/xuexidazi.git` → `/opt/xuexidazi` |
| 新 API 反代 | 建议 `sy-api.xuexidazi.site` → `http://127.0.0.1:3070` |

新域名为建议名称，需实际解析、配置证书；若换名称，全文一起替换。现有 `api.xuexidazi.site → 3050`、`xuexidazi.site → 8090`、`qiway.site → 3010` 三条反代保持原样。

## 1、从 Git 拉程序，准备已有内容

**服务器宝塔终端：首次拉取失业有数，更新原 padmin 源码。**

```bash
cd /opt
git clone https://github.com/randyzhou2025/unemployment-hub.git unemployment-hub
cd /opt/xuexidazi
git pull --ff-only
mkdir -p /opt/backups/unemployment-hub
chmod 700 /opt/backups/unemployment-hub
```

以下只在**首次迁移本机运营内容**时做。程序从 Git 拉取，只有数据库备份通过 `scp` 传输；数据库不进入 Git。导出期间暂停本机后台编辑。

**Mac 终端**，把 SSH 地址换成真实服务器：

```bash
export UH_SERVER='root@你的服务器IP'
cd /Users/Randy/Cursor/UnemploymentHub
mkdir -p /Users/Randy/Downloads/unemployment-deploy
chmod 700 /Users/Randy/Downloads/unemployment-deploy
docker compose -f deploy/compose.dev.yml up -d --wait db
umask 077
docker compose -f deploy/compose.dev.yml exec -T db \
  pg_dump -U uh -d unemployment_hub -Fc --data-only --no-owner --no-acl \
  -t public.sources -t public.contents -t public.content_revisions \
  -t public.app_config -t public.feedbacks -t public.audit_logs \
  > /Users/Randy/Downloads/unemployment-deploy/content.dump
test -s /Users/Randy/Downloads/unemployment-deploy/content.dump
scp /Users/Randy/Downloads/unemployment-deploy/content.dump \
  "$UH_SERVER:/opt/backups/unemployment-hub/content.dump"
```

## 2、服务器启动 API，更新 padmin

逐块执行，任何命令报错先停下。沿用服务器已有 Docker 和宝塔。

**配置失业有数的服务端环境文件。** Git 不包含真实密码，首次部署单独创建；以后 `git pull` 不覆盖它。

```bash
cd /opt/unemployment-hub
test -f .env.prod || cp deploy/production.env.example .env.prod
chmod 600 .env.prod
nano .env.prod
```

填入下面的配置。三个密码使用不同随机值，可用 `openssl rand -hex 24` 分别生成；数据库 URL 的密码与第一行一致。

```dotenv
POSTGRES_PASSWORD=数据库密码
DATABASE_URL=postgres://uh:数据库密码@db:5432/unemployment_hub
ADMIN_USERNAME=admin
ADMIN_PASSWORD=独立后台密码至少16位
ADMIN_ORIGINS=https://xuexidazi.site
WECHAT_MINI_APPID=wx4705822b30adb794
WECHAT_MINI_SECRET=这个小程序独立的AppSecret
PADMIN_GATEWAY_SECRET=后台连接密钥至少32位
```

`nano` 保存：`Ctrl+O`、回车，退出：`Ctrl+X`。AppSecret 只填在服务器文件中。

**构建 API、创建数据库表。** 后台复用 padmin，不需要启动独立 `web` 服务。

```bash
docker compose --env-file .env.prod -f deploy/compose.prod.yml config --quiet
docker compose --env-file .env.prod -f deploy/compose.prod.yml build api
docker compose --env-file .env.prod -f deploy/compose.prod.yml up -d --wait db
docker compose --env-file .env.prod -f deploy/compose.prod.yml run --rm api node dist/db/migrate.js
```

**首次上线导入内容。** 先检查下面六项都是 `0`；如果已有数据，不执行导入，避免混入两份运营内容。

```bash
docker compose --env-file .env.prod -f deploy/compose.prod.yml exec -T db \
  psql -U uh -d unemployment_hub -c \
  'SELECT (SELECT count(*) FROM contents) AS contents, (SELECT count(*) FROM content_revisions) AS revisions, (SELECT count(*) FROM sources) AS sources, (SELECT count(*) FROM app_config) AS config, (SELECT count(*) FROM feedbacks) AS feedbacks, (SELECT count(*) FROM audit_logs) AS audit;'
```

六项为 `0` 后，首次导入并启动：

```bash
docker compose --env-file .env.prod -f deploy/compose.prod.yml exec -T db \
  pg_restore -U uh -d unemployment_hub --data-only --no-owner --no-acl \
  --single-transaction --exit-on-error < /opt/backups/unemployment-hub/content.dump
docker compose --env-file .env.prod -f deploy/compose.prod.yml run --rm api node dist/db/seed.js
docker compose --env-file .env.prod -f deploy/compose.prod.yml up -d api
curl --fail http://127.0.0.1:3070/api/health/ready
```

看到 `{"status":"ready"}` 再继续。

**从 API 镜像取出已构建的管理工作台。** 这一步替代上传编译产物；每次更新管理界面后都执行。

```bash
mkdir -p /opt/xuexidazi/integrations/unemployment-workbench
docker cp "$(docker compose --env-file .env.prod -f deploy/compose.prod.yml ps -q api)":/app/apps/admin/dist/. \
  /opt/xuexidazi/integrations/unemployment-workbench/
```

**接入原 padmin。** 保留原有数据库和 JWT 等配置，只新增或修改三项：

```bash
cd /opt/xuexidazi
cp -p .env.prod ".env.prod.bak-$(date +%Y%m%d-%H%M%S)"
nano .env.prod
```

```dotenv
UNEMPLOYMENT_API_ORIGIN=http://unemployment-api:4000
UNEMPLOYMENT_GATEWAY_SECRET=与失业有数PADMIN_GATEWAY_SECRET完全一致
UNEMPLOYMENT_DOCKER_NETWORK=unemployment-hub_default
```

保存后执行。更新会短暂重启 `xuexidazi.site` 服务，其他项目不重启。

```bash
docker compose --env-file .env.prod -f docker-compose.prod.yml -f docker-compose.unemployment.yml config --quiet
docker compose --env-file .env.prod -f docker-compose.prod.yml -f docker-compose.unemployment.yml build xuexidazi
docker compose --env-file .env.prod -f docker-compose.prod.yml -f docker-compose.unemployment.yml up -d --no-deps xuexidazi
curl --fail http://127.0.0.1:8090/padmin/api/health
```

看到 `{"ok":true}` 后，打开 **`https://xuexidazi.site/padmin/unemployment/users`**，用原管理员账号登录，检查失业有数菜单、资讯与政策。

## 3、宝塔配新域名，发布小程序

1. 域名控制台：将 `sy-api.xuexidazi.site` 的 A 记录指向服务器公网 IP。
2. 宝塔「反向代理 → 添加反代」：域名填 `sy-api.xuexidazi.site`，代理地址填 **`http://127.0.0.1:3070`**。
3. 为新反代申请 SSL 证书并启用 HTTPS。原有三条反代不修改。

**服务器检查公网 API：**

```bash
curl --fail https://sy-api.xuexidazi.site/api/health/ready
curl --fail 'https://sy-api.xuexidazi.site/api/v1/contents?region=310000'
```

第一条返回 `ready`、第二条返回已有资讯后，在微信公众平台此 AppID 的「开发管理 → 服务器域名」中，将 **`https://sy-api.xuexidazi.site`** 加入 `request 合法域名`。

**Mac 终端构建正式小程序：**

```bash
cd /Users/Randy/Cursor/UnemploymentHub
printf '%s\n' 'VITE_API_BASE=https://sy-api.xuexidazi.site' > apps/miniapp/.env.production
VITE_API_BASE=https://sy-api.xuexidazi.site pnpm release:weapp
```

微信开发者工具导入 **`/Users/Randy/Cursor/UnemploymentHub/apps/miniapp/dist/build/mp-weixin`**，确认域名校验开启，点击「上传」。公众平台按 **设为体验版 → 真机验收 → 提交审核 → 审核通过后发布** 操作。

真机用蜂窝网络检查资讯与各模块；同一微信打开两次，padmin 只新增一个用户。完成实际验收和微信发布后才算上线。

**以后更新：**两个仓库分别执行 `git pull --ff-only`；API 继续执行构建、迁移、`up -d api`；工作台按上文从新 API 容器复制，再构建并更新 padmin。不要重复导入本机 `content.dump`，也不重建数据库。小程序代码有变更时，重复第 3 步的构建与微信发布。

本文命令已按仓库配置核对，尚未在云服务器执行。参考：[Docker Compose run](https://docs.docker.com/reference/cli/docker/compose/run/)、[up](https://docs.docker.com/reference/cli/docker/compose/up/)、[PostgreSQL pg_dump](https://www.postgresql.org/docs/17/app-pgdump.html)、[pg_restore](https://www.postgresql.org/docs/17/app-pgrestore.html)。
